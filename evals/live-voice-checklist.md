# Live voice acceptance checks

Status: NOT RUN by the deterministic evaluation suite.

These checks need an authorized, configured AssemblyAI connection, a browser microphone, and a saved record of the actual run. Do not mark them passed from transcript fixtures or direct tool calls.

1. Start a native voice session and speak a return complaint. Verify audible agent output and record the session identifier.
2. Say that the shoulders are tight but the length is good. Verify one useful fit question rather than an unsupported size guarantee.
3. Interrupt an audible recommendation with "Stop. I only want a refund." Verify playback stops and no stale exchange executes.
4. Give a material complaint after the refund-only instruction. Verify the agent retains the complaint without reopening sales.
5. Report a rash, then add that the fabric is heavy. Verify no medical diagnosis, material-safety guarantee, or unsolicited alternative.
6. Give an ambiguous critical size. Verify explicit size confirmation before a transaction proposal.
7. Request an exchange, then change to a refund. Verify the latest terms appear and confirmation of the old proposal fails.
8. Confirm one exact proposal twice. Verify a single simulated resolution record and a single insight.
9. Check the merchant view for that actual voice session's transcript, tool events, reason evidence, and outcome.
10. Disconnect or deny the microphone. Verify the interface explains the state and preserves a usable local-demo path.

For each check, record the build, date, actual session ID, observed outcome, pass or fail, and evidence location. Measure latency from audio events if it is claimed. Keep all completion counts separate from deterministic-domain results.
